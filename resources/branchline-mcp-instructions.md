Branchline is strictly for consequential Git and GitHub effects: real-repository commits, Git pushes, PR/release/repository changes, history rewrites, destructive Git operations, and Git/GitHub authentication or repository-security changes. Read-only queries, safe local Git work, builds, and disposable isolated fixture tests use normal tools.

Unrelated services, including Convex configuration, databases, deployments and cloud administration, use their normal tools and permissions even for remote or sensitive changes. Being in a repository does not change this boundary. Classify scripts/wrappers by actual effects; inspect or clarify unknown effects instead of defaulting to Branchline.

Approve the entire unchanged Git/GitHub workflow, including supporting setup/checks. Compose unrelated service mutations separately with their own authorization. If a user supplies a chain mixing a gated Git/GitHub action with unrelated service mutations, explain the conflict and ask before splitting/changing it or submitting it wholesale. Branchline approval grants no other service's permissions.

Choose an explicit absolute repositoryPath or known repositoryId; the visible app repository is not the target selector. Explain outcome, reason, targets and uncertainty.
