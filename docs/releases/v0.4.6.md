Keep useful approval details visible when a command chain starts with dynamic checks.

### Fixed

- A shell substitution in a preflight check no longer hides structured previews for every later action in a safely separated command chain.
- Show later literal stage, commit, push, pull-request, and release arguments while keeping unresolved checks grouped under exact-command review.
- Keep primary-branch warnings visible for a later literal push to main or master, even when an earlier check contains a shell substitution.
- Treat later working-directory state, current branch and file contents as unknown after an unresolved expression. Message and notes files are not read from an uncertain context.
- Keep commands nested inside substitutions, comments, and quoted strings out of the action list. Ambiguous compound syntax continues to use exact-command review.

Previewing never executes substitutions or changes the command. Approval still covers the whole unchanged command, and execution records the actual process result.

### Update

Choose **Branchline → Check for Updates…** and select **Install & restart**. Automatic checks remain quiet unless an update is available.

For a fresh installation, or versions through 0.4.2:

```sh
curl -fsSL https://raw.githubusercontent.com/ShindouMihou/branchline/main/scripts/install.sh | bash
```

Quit Branchline before running the installer. The default destination is `~/Applications/Branchline.app`.

Apple Silicon macOS 12 or later. This preview is ad-hoc signed and is not notarized; normal macOS security policy applies.

Validated with 173 Rust tests and the existing 68 frontend, 11 installer, and two release-manifest checks. Includes a regression for the release workflow that exposed this issue.
