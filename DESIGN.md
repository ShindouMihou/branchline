# Branchline visual direction

A quiet, soft-black developer tool with a compact information hierarchy. Git operations remain where existing users expect them: branch and remote controls above, changes or commit details at left, history and diffs in the primary workspace.

## Palette

- Canvas: #111214
- Sidebar and tool surfaces: #161719
- Raised controls: #1C1D20
- Structural border: #2D2E32
- Primary text: #D9DADD
- Secondary text: #A6A7AB
- Selected surface: #2B2930
- Lavender detail: #AFA7C9

Primary actions use a subdued off-white with dark text. The canvas is lifted slightly above black, body text is dimmed from white, and semantic/graph colors are desaturated to reduce glare without weakening small-label contrast. Lavender identifies selection and history; it does not fill large panels. Green and red are reserved for Git status, additions, removals, and errors. File content uses SF Mono/Menlo; the interface uses the macOS system font. Body and code text remain readable at 13–14px, with 12px supporting labels.

## Layout

The toolbar, notification banners, workbench, and status bar are separate rows in normal document flow. The tool rail belongs to the workbench, so expanding a banner cannot overlap navigation. Recovery refs are collapsed by default and wrap when expanded.

The log remains a table with a real parent graph, branch labels, author, date, and hash. Subtle surface changes and thin borders establish hierarchy. Menus and dialogs use softly rounded corners and restrained shadows. No remote fonts or UI assets are loaded.

## Logo

The mark is a continuous branching line with rounded terminals, drawn as an original vector. The long stem suggests the main line of history; the ascending branch suggests work diverging from it. Omitting node circles gives it a compact silhouette at menu-bar and toolbar sizes. The app icon places the white mark on a black rounded tile. A lowercase wordmark uses tight spacing for a quieter application header.

Editable assets are in assets/: branchline-mark.svg, branchline-wordmark.svg, and icon.svg. Raster and platform icons are generated by the Tauri icon command.

## Personal appearance and glanceability

Version 0.3 adds live, locally persisted controls for interface font size, diff font size, list/diff spacing, and dark contrast. Contrast interpolates the main surfaces and text together; supporting labels keep an 11 px minimum when interface text is reduced. Defaults use comfortable spacing and a soft dark palette.

A simplified view is on by default. It removes duplicate rail navigation and sidebar headings, collapses shortcut help, omits date/hash columns from the main log, and presents an All clear state for clean repositories. Selected commit details retain author/date/hash information. Disabling simplified view restores the extra navigation and metadata.

One repository picker shows the active repository name. Branch selection is a quiet text-and-icon control with hover and focus states. Incoming operations share an Update split button: the main action fetches and pulls, and the dropdown checks the remote without pulling. Push stays separate. A remote-branch badge and directional counters show outgoing and incoming commits. These choices reduce the number of controls visible before a user needs them.


## Automatic local updates

No Refresh toolbar control. Native filesystem signals update local changes, index, refs, and history quietly, with a periodic safety audit. Preserve file/commit selection, diff scroll, drafts, and loaded history pages when unchanged. Defer updates during dialogs, menus, active operations, and immediate interaction. Never fetch or pull as part of local refresh; Command+R remains a recovery shortcut.

## AI requests and global connections (0.4)

The first form-heavy approval prototype was rejected. The implemented revision uses a vertical connected timeline with Git-action icons and one expanded step. The branch, connection and outcome appear once. Actual diffs use a small file header and added/removed lines; raw index hashes stay out of the default reading surface. The decision footer stays outside the scroll area.

The AI note uses a short explanation with a readable line width. Expansion separates What changes from What to watch for, removes the repeated headline, and moves attribution/model details to a keyboard-accessible info control. Explanations are untrusted; verified Git effects remain separate.

Activity has its own command timeline. Commands expand individually; timestamps, approval scope, paired connection and self-reported model remain inspectable. Copy for AI exports a concise receipt without full source; file export retains the complete local record.

Connections are global client identities. The repository-list restriction was explicitly rejected. One MCP configuration works with any local Git repository path; source-diff reading is a separate connection-wide preference. Setup is a two-step branded onboarding flow: choose client/name, then follow client-specific global/project installation instructions. Connected-client cards show client icons, type, setup reopening, and source-read preferences. The connector and review-prompt settings remain distinct.

Publishing red flags are computed by Rust from actual refs: main/master destinations and mismatched source/target names. Show the exact route, keep warnings visible even when Push is collapsed, require acknowledgement of each flag, and preserve acknowledgement codes in receipts. These warnings do not assert that a hosting provider has branch protection enabled.

The connector may open the app and show a fresh review request when enabled. Duplicate requests do not create repeated prompts; an open review remains selected while new requests join the inbox. Existing dialogs defer the review surface. No mutation is approved by opening the app.


Approval actions use persistent button surfaces: Decline and Commit only are neutral secondary buttons; Approve stays primary. Stop remaining uses the same secondary treatment during execution. Hover adds feedback without establishing the control's basic visibility.

## Review panel structure

The selected-commit sidebar uses an explicit label, readable subject, labeled author/date/hash rows, a copy-hash control, and a separate Files changed heading. File rows show the basename first and the directory second.

Files, commit list, and diff panels have subtle collapse controls and draggable dividers. Sizes and collapsed state persist; keyboard arrows resize, Home/End clamp, and double-click resets a divider. The last visible review pane stays open. Commit selection count and help sit at the toolbar’s right edge. Only the top help tooltip remains, with wrapping and overflow outside the log pane.

Branch actions belong in a compact menu anchored to the selected row (or right-click point), not in a persistent block below the list. Opening the picker uses a repository-specific background snapshot immediately; Reload or ⌘R refreshes the local list without fetching from the network.
